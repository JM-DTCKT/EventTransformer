# EvT 가속기 — DVS128 10-class, ZCU102

DVS 이벤트 카메라의 제스처 인식 모델 **EvT(Event Transformer)** 를 ZCU102(xczu9eg-2)
PL 에 올린 추론 가속기입니다. attention 3블록 · head 4개를 포함한 전체 망이 보드에서
돌고, 264 샘플 정확도가 골든과 일치합니다.

```
클럭      187.5 MHz  (IOPLL / 8)          WNS +0.008 ns, 실패 엔드포인트 0 / 574,315
정확도    258 / 264 = 97.72 %             골든 97.34 % (257/264) 대비 +1
속도      8,677 µs / 샘플                 264 샘플 2,290 ms
연산기    DSP48E2 1,976 (78.4 %)          32×32 시스톨릭 배열 1,024 + 주변
```

---

## 1. 보드 실행 결과

ZCU102 실측입니다. 세 클럭 모두 **같은 264 샘플**을 DDR 에서 읽어 돌렸습니다.

| | 100 MHz | 150 MHz | **187.5 MHz** |
|---|---|---|---|
| 샘플당 | 16,765 µs | 11,207 µs | **8,677 µs** |
| 264 샘플 총 | 4,426 ms | 2,958 ms | **2,290 ms** |
| 엔진 사이클 | 1,662,996 | 1,666,907 | **1,612,179** |
| **정확도** | 258 / 264 | 258 / 264 | **258 / 264 (97.72 %)** |
| 처리율 | 59.6 샘플/s | 89.2 샘플/s | **115.2 샘플/s** |
| 100 MHz 대비 | 1.000× | 1.496× | **1.932×** |

**정확도는 세 조건에서 한 샘플도 다르지 않습니다.** 클럭을 1.875배 올리고 RTL 을
다섯 곳 고쳤는데 결과가 동일합니다.

한 샘플은 타임스텝 20개 × 24 ms = **480 ms 분량의 이벤트 데이터**입니다. 8.677 ms 에
처리하므로 **실시간 대비 55.3배속**입니다.

하드웨어가 6개를 틀리는데 그중 5개는 골든도 틀립니다. 하드웨어만 맞히는 샘플이 하나
있어 258 이 됩니다. **틀리는 샘플 목록이 겹친다**는 것이 양자화·연산 순서가 아니라
모델 자체의 한계임을 보여줍니다.

```
        PS (APU 1200 MHz, DDR 533 MHz)          │          PL (187.5 MHz)
                                                 │
  A53 ──┬── M_AXI_HPM0_FPD (AXI4-Lite 32b) ──── smc_ctrl ──┬── axi_dma_0  (제어)
        │                                        │          └── top        (제어)
        │                                        │
        └── S_AXI_HP0_FPD  (AXI4 128b) ───────── smc_data ──── axi_dma_0  (데이터)
                                                 │                  │
                                                 │            AXI-Stream 128b
                                                 │                  ↓
        DDR ←──────────────────────────────────  │          top ── EvT_Engine
                                                 │
                                    비동기 브리지 (PS 내장)
```

**PS 와 PL 은 비동기입니다.** A53 은 APLL(1200 MHz), DDR 은 DPLL(533 MHz), PL 은
IOPLL/8(187.5 MHz)로 서로 다른 PLL 에서 나옵니다. PS-PL AXI 포트에 비동기 FIFO 가
내장돼 있어 **PL 주파수만 바꿔도 PS 는 영향이 없습니다** — 100 → 150 → 187.5 MHz 변경이
`psu_init` 한 줄로 끝난 이유입니다.

## 4. 실행 모델

가속기는 **자기 명령어 프로그램**을 돕니다. CPU 의 fetch–decode–execute 와 같은
구조입니다.

```
IDLE → TLOAD → FETCH → DEC → GCONST → RUN → WAIT → NEXT → … → TSTEP → DONE
                 ↑                                    │
                 └────────── 다음 inst ────────────────┘
```

| 상태 | 하는 일 |
|---|---|
| **TLOAD** | 타임스텝 시작 — 입력 활성값 · `pos_idx` 적재 |
| **FETCH** | `Inst_Mem` 에서 256비트 inst 워드 읽기 |
| **DEC** | `q_kind`·`q_cons`·`q_AIN`·`q_AOUT` 등으로 펼침 |
| **GCONST** | 상수(bias · 곱수) 준비 3사이클 |
| **RUN** | `q_kind` 에 따라 해당 유닛 기동 |
| **WAIT** | 유닛 완료 대기 (RES · MEAN 은 여기서 직접 위상 기계를 돌림) |
| **NEXT** | inst 포인터 `sp` 증가 |
| **TSTEP** | 타임스텝 경계 — latent 이월 |

### 프로그램 길이

```
body 118 inst   ← 타임스텝마다 반복
tail   5 inst   ← 샘플 끝에 한 번
──────────────
한 샘플 = 118 × T + 5      (T ≤ 20)
```

inst 종류는 7가지입니다: `GEMM` · `LN` · `SMAX` · `RES` · `MEAN` · `ARGMAX` · `POS`.

### 토큰 흐름 제어

타임스텝마다 유효 토큰 수(`n_tok`)가 16~123 으로 달라집니다. 엔진이 `tok_req` 를 올리면
PS 가 해당 타임스텝의 X 타일을 DMA 로 채우고 `tok_ack` 로 답합니다. 샘플당 최대 20회
왕복하며, 이 구간이 전체의 **0.9 %** 입니다 (샘플당 79 µs).

### inst 워드 (256b)

`EvT_Engine.v` 디코더와 한 벌입니다.

```
[ 31: 0] KIND[3:0] CONS[5:4] ACT[7:6] VAR[11:8] FLAG[15:12]
         SHIFT[21:16] GSH[27:22] FLAG2[31:28]
[ 63:32] M        [ 95:64] K        [127:96] NOUT
[159:128] AIN     [191:160] BIN     [223:192] AOUT
[255:224] PB[15:0] | OSTR[31:16]

KIND  0 GEMM  1 LN  2 SMAX  3 RES  4 MEAN  5 ARGMAX  6 POS
CONS  0 int8(+ACT)  1 Q4.11→GELU→int8  2 bf16  3 Q6.9(softmax 직결)
VAR   [0] M←n_tok  [1] NOUT←Lk  [2] K←Lk  [3] C←Lk
FLAG  [0] Transpose32 경유  [1] head-major(OSTR=head stride)  [2] B는 A_Mem
      [3] raw16 — Q4.11 을 int8 로 안 내리고 16비트 그대로 저장
FLAG2 [0] LayerNorm 입력이 Q4.11 정수 코드
      [1] RES 두 피연산자가 정수 코드 — PB/OSTR 의 fx 상수로 스케일
      [2] B 에 bias 토큰이 붙음 (AOUT=bias_k, OSTR=bias_v, PB=스칼라)
      [3] 활성함수 뒤 2차 재양자화
```

필드 하나가 inst 종류에 따라 다른 뜻을 갖습니다 — 워드를 늘리는 대신 **그 inst 에서
확실히 노는 칸**을 씁니다. QK 는 메모리에 안 써서 `AOUT` 이 놀고, AV 는 행타일이
하나라 `OSTR` 이 놉니다.

## 6. 모듈별 설명

### `top` — 보드 최상위

AXI4-Lite 제어 레지스터 파일과 AXI-Stream 데이터 경로를 감싼 래퍼입니다. PS 가 쓰는
레지스터(`start`, `n_body`, `n_tail`, `n_time`, `eps`, `tok_n`, `tok_ack`)를 받아
엔진에 넘기고, 엔진의 `done`·`busy`·`res_class`·`res_logits` 를 되돌려줍니다.
`VERSION` 레지스터(`0xA001_001C` = `0x45565401`)로 비트스트림을 확인합니다.

### `core/` — 엔진 데이터패스

**`EvT_Engine`** (1,029줄, 전체의 20 %)

inst 실행 FSM 이면서, 하위 모듈로 분리되지 않은 로직을 직접 품고 있습니다.

| 내부 블록 | 하는 일 |
|---|---|
| **A_Mem 포트 중재** | 읽기 2포트(`ar_*`/`br_*`)를 GEMM·LN·RES·MEAN·POS 가 나눠 씀. 동시에 도는 유닛이 없도록 스케줄이 보장하되, **GEMM 만은 A 와 B 를 동시에** 읽음 |
| **`RESLANE`** | 잔차 덧셈 32레인. bf16 경로는 `Fp32_Add`, 정수 경로는 곱셈 2개 + `Int32_To_Bf16` |
| **`ARGMAX`** | 최종 분류. `acc·M[c]` 를 64비트로 비교해 최댓값 추적 |
| **`MEAN`** | 평균 풀링. 32입력 덧셈 트리 + 재양자화 |
| **지연선 `nq`/`mq`** | 출력 포맷(2~9단)에 맞춰 A_Mem 쓰기 주소를 늦춰 데이터와 짝을 맞춤 |
| **토큰 핸드셰이크** | `tok_req` / `tok_ack` — PS 가 타임스텝마다 X 를 채워줌 |

**`Format_Cast_Act`**

GEMM 이 뱉는 INT32 누산값을 다음 레이어가 원하는 포맷으로 바꿉니다. bias 덧셈 +
역양자화·재양자화 + 포맷 변환 + 활성함수를 한 파이프라인에 융합해 **추가 사이클 없이**
GEMM 출력에 붙어 흐릅니다.

| `CONS` | 경로 | 단수 |
|---|---|---|
| 0 INT8 | requant → [ReLU] → int8 | 3 |
| 1 Q4.11 | requant → **GELU** → requant → int8 | 9 |
| 2 BF16 | bf16((acc+b) × step) | 2 |
| 3 Q6.9 | requant → Q6.9 → softmax 직결 | — |

경로마다 길이가 달라, 엔진이 지연선으로 쓰기 주소를 2~9사이클 늦춥니다. GEMM 이 한
사이클에 32개 값을 내놓으므로 후처리도 **32레인 병렬**입니다.

**`Pos_Gather`**

위치 임베딩을 온칩 표에서 찾아 A_Mem 에 씁니다. 예전에는 호스트가 타임스텝마다
pos enc 를 워드 레이아웃으로 펴서 DDR 에 올렸고 그 이미지가 **96.7 MB** 였습니다.
실제 정보량은 표 27.6 KB + `pos_idx` 0.47 MB 뿐이라 200배를 펼쳐 보낸 셈이었습니다.

표를 **행 단위로 넓게**(한 행 = 64특징 = 512b) 두면 한 토큰의 64개 값이 한 번의 읽기로
나오고, 나머지는 축 전환 문제가 됩니다:

```
① 표에서 32행 읽기      96 사이클
② 32×64 버퍼에 쌓기
③ A_Mem 에 64워드 쓰기  64 사이클      ≈ 160 사이클 / 타일
```

타임스텝당 최대 4타일 = 650 사이클로, 전체의 **0.1 %** 입니다.

**`Transpose32`**

32×32 바이트 corner-turn — 행으로 쓰고 열로 읽습니다.

```
쓰기 워드 d :  wdata 의 바이트 t  =  X[t][d]
읽기 워드 t :  rdata 의 바이트 d  =  X[t][d]
```

시스톨릭 코어는 A·B 둘 다 "워드 = reduce 인덱스" 로 읽는데, `attn·V` 만 reduce 축이
`d` → `j` 로 바뀝니다. **V 만 축을 돌려야** 해서 이 모듈이 있습니다.

**`Bram_Sdp`**

**SDP(Simple Dual Port)** — 쓰기 1포트 + 읽기 1포트, 서로 독립된 주소. 바이트 단위
write enable 을 지원하고 읽기 지연은 1사이클입니다. 37줄짜리 이 모듈 하나가 파라미터만
바꿔 **5종류 메모리 전부**를 만듭니다.

### `axi/` — 호스트 인터페이스

**`Axis_Loader`** — AXI-Stream 128b 를 받아 온칩 메모리에 순차 적재합니다. 목적지
(`sel`)와 시작 워드(`base`)를 AXI-Lite 로 잡은 뒤 스트림을 흘리면, 소프트웨어가 넘긴
버퍼가 곧 메모리 이미지가 됩니다. **RTL 에 주소 계산 로직이 없어** 디버깅할 게
없습니다 — 순서 재배치는 전부 호스트 쪽 파이썬이 미리 합니다.

**`Axis_Dump`** — A_Mem 구간을 읽어 DMA S2MM 으로 DDR 에 내보냅니다. **포맷 경계마다
중간 활성값을 대조**해야 해서 결과값만이 아니라 내부 상태를 꺼내올 수 있어야 합니다.
엔진이 쉴 때만 동작합니다 (A_Mem 읽기 포트를 나눠 씀).

### `gemm_core/` — 32×32 시스톨릭 배열

**`Gemm_Core`**

output-stationary 시스톨릭 GEMM. 타일 순서기와 드레인을 담당합니다. `fpga_nl` 판과
**연산은 완전히 동일**하고 딱 하나가 다릅니다 — **B 피연산자의 출처를 코어가 정하지
않고 주소만 내보냅니다.** 그래서 Linear · `Q·Kᵀ` · `attn·V` 세 종류가 코어 한 벌을
씁니다.

공용 타일 순서기(`CLR→STREAM→RD→NEXT`)는 타일이 겹칠 수 없어 쓰지 않고, 여기서만
쓰는 순서기를 직접 둡니다.

**`PE_Array_Pp`**

정방 mesh. A 는 좌→우, B 는 위→아래로 흐르고, 여기에 **파면 두 개가 더** 흐릅니다:

```
clr    좌→우    A 와 같은 방향·같은 속도
snap   좌→우    마찬가지
```

둘 다 A 와 같은 속도라 PE[i][j] 는 **자기가 확정되는 사이클에** 값을 받습니다.

**`PE_OS_Pp`** — DSP 1,024개의 실체

원본 `PE_OS` 는 누산기가 DSP48E2 의 P 하나뿐이라, 컬럼을 다 뽑아낼 때까지 다음 타일을
시작할 수 없었습니다. 타일 주기 `K+114` 중 실제 곱셈은 `K` 뿐이었습니다.

```
P       : 지금 타일을 누적                 (ping)
shadow  : 직전 타일의 최종값을 들고 있음   (pong)  ← 읽어내기는 여기서
```

**ping-pong 누산기**로 드레인과 다음 타일 계산이 겹칩니다.

**`Skew_Buf`** — 시스톨릭 정렬용 삼각형 지연 버퍼

원래 피더는 레인마다 **다른 주소**를 읽어야 했습니다 (`a_edge[i] = a_mem[mt*N+i][c-i]`).
뱅크 32개가 각각 독립 주소를 받아야 해서 메모리를 32조각으로 쪼개야 했는데, 이 버퍼가
그 요구를 없앱니다 — 메모리는 한 워드씩 읽고, 스큐는 버퍼가 만듭니다.

### `layernorm/`

**`layernorm_top`** — 엔진 어댑터. A_Mem 읽기, affine, 재양자화를 붙여 엔진 규약에
맞춥니다.

**`layernorm_unit`** — 32행 타일 단위 D축 LayerNorm (bf16 in / Q4.11 out).

```
for r in 0..31:  y[r][0..127] = (x[r][.] - mu[r]) / sqrt(var[r] + eps)
```

한 타일은 **32행 × 128열**이고, 매 클럭 "한 열"(32행 × 16b = 512b, A_Mem 워드 폭과 일치)
을 받습니다. 세 단계를 **타일 3개에 걸쳐 파이프라인**합니다:

| 단계 | 하는 일 | 길이 |
|---|---|---|
| S1 | 수신하며 `sum_x`·`sum_x2` 누산 | 128 |
| S2 | 분산 → `rstd` (역제곱근) | 약 38 |
| S3 | 정규화 후 출력 | 128 |

**분산을 정수 그대로** 구해 상쇄오차를 원천 제거합니다:

```
var = 2^-(2IF+2DLOG) · ( (SQ << DLOG) - SX·SX )
```

괄호 안이 오차 없는 정수식이라 Cauchy-Schwarz 에 의해 **결과가 절대 음수가 되지
않습니다.** 나눗셈도 없습니다 — `mu` 는 `SX` 를 소수점만 바꿔 읽은 값입니다.

**`LN_Affine`** — 곱셈기 1개 + 고정 시프트.

```
y = sat( (xhat·gamma + (beta << BSHIFT) + (1 << (OSHIFT-1))) >> OSHIFT )
```

세 피연산자가 전부 고정소수점 코드라 스케일이 정적으로 정해집니다.

**`rsqrt_unit`** — 정규화 + PWL LUT 방식의 역제곱근. `layernorm_unit` 만 씁니다.

### `softmax/`

**`softmax_top`** — 엔진 어댑터. 인터페이스가 예전 판과 한 글자도 다르지 않아
`EvT_Engine` 은 안쪽 코어가 바뀐 줄 모릅니다.

**`softmax_unit`** — 32행 타일 단위 T축 softmax (Q6.9 in / Q1.14 out).

`layernorm_unit` 과 같은 구조로 매 클럭 한 열(512b)을 받고, **수신하면서 max 를 확정**
합니다. 별도 패스가 없습니다.

예전 판은 레인 하나를 시분할해 `4·N·C ≈ 6,800` 사이클이 들었고 이를 36번 돌아
**타임스텝 53만 사이클 중 약 24만**을 softmax 가 썼습니다. 새 코어가 그걸 없앴습니다.

**`exp2_unit`** — softmax 의 exp 입력은 항상 `z = x − max ≤ 0` 이라 `exp(z) ∈ (0,1]`
입니다. 자연지수를 그대로 근사하지 않고 **base-2 로 바꾼 뒤 "정수부는 시프트,
소수부만 LUT"** 로 처리합니다. 레인당 1벌씩 32개.

**`recip_unit`** — 나눗셈 `y_i = e_i / S` 를 "역수 한 번 + 곱셈 N 번"으로 바꿉니다.
`S` 는 exp 결과의 합이라 범위가 넓은데, **2의 거듭제곱으로 정규화해 LUT 정의역을
[1,2) 로 좁힙니다.** 행별 1벌.

### `gelu/`

**`gelu_pwl`** — Q4.11 → Q4.11 구간선형 GELU. `gelu_lut.vh` 에 base/delta 64쌍이
들어 있고, `Format_Cast_Act` 의 Q4.11 경로에서 32레인 병렬로 씁니다.

### `activation/`

**`Activation`** — requantizer 뒤에 붙는 활성함수, 32레인 병렬 순수 조합. 레이어마다
런타임으로 골라야 하므로(마지막 레이어는 활성함수 없음) 파라미터가 아니라 **입력
포트**(`act_sel`)로 선택합니다.

### `requant/`

**`Requant_Int`** — 데이터패스의 유일한 정수 재양자화기 형태입니다.

```
out = sat( (acc·M + (1 << (sh-1))) >> sh )

acc : GEMM 누산기(INT32) 또는 앞단 Qm.n 코드
M   : 오프라인 상수.  M[c] = round(s_x · s_w[c] / lsb_out · 2^sh)
```

**역양자화와 재양자화를 한 곱수로 접어** 곱셈 하나로 끝냅니다. `M[c]` 는 오프라인
캘리브레이션(학습 배치 100개 absmax)에서 정해집니다.

**`Requant_Bf16`** — INT32 → bf16. 100 MHz 대비 타이밍을 위해 **곱셈 뒤에서 한 단**
끊었습니다 (`CP_LAT_B` = 2).

### `vector_alu/`

| 모듈 | 하는 일 |
|---|---|
| **`Fp32_Add`** | FP32 가산기 2단. 잔차 경로에서 씀. 1단은 크기 비교 → 지수 정렬(배럴 시프터) → 가감산, 2단은 정규화 |
| **`Fp32_To_Bf16`** | FP32 → bf16 (상위 16비트 + 반올림) |
| **`Int32_To_Bf16`** | INT32 → bf16 (LZC + 정규화) |
| **`bf16_to_fix`** | bf16 → 고정소수점. `sh = e + SH_OFS + xsh` 라 **입력 지수에 의존** |
| **`Q411_To_Fix`** | Q4.11 → 고정소수점. `sh = SH_OFS + xsh` 로 **입력과 무관** |

`bf16_to_fix` 와 `Q411_To_Fix` 는 `layernorm_unit` 의 입력단에서 **병렬로 놓고 mux 로
고릅니다.** 예전에는 Q4.11 을 bf16 으로 올려서 넣었는데, 그러면 정규화(LZC + 좌시프트)와
역정규화(우시프트)가 한 사이클에 **직렬**로 놓여 8.475 ns 가 됐습니다. 각자 목표
포맷까지 바로 가서 mux 로 합치면 깊이가 절반이 됩니다.

## 7. 메모리

| | 폭 × 깊이 | 사용 |
|---|---|---|
| **A_Mem** | 512b × 8,192 **× 2 미러** | 7,649 워드 |
| W_Mem | 256b × 16,384 | 14,000 워드 (437 KB) |
| PB_Mem | 256b × 1,024 | 860 워드 |
| PG_Mem | 256b × 256 | 208 워드 |
| Inst_Mem | 256b × 256 | 123 워드 |

### A_Mem 이 미러 2벌인 이유

GEMM 만은 **A 와 B 를 동시에 읽습니다.** `Q·Kᵀ` 와 `attn·V` 는 둘 다 A_Mem 이라
읽기 2포트가 필요한데, RAMB36E2 는 물리적으로 포트가 2개뿐이라 쓰기가 하나를 쓰면
읽기는 하나만 남습니다. **2R+1W 를 동시에 하려면 복사본이 물리적으로 필요합니다.**

```
u_amem0   쓰기 aw_*  ·  읽기 ar_*     GEMM(A) · LN · MEAN · POS · RES(A)
u_amem1   쓰기 aw_*  ·  읽기 br_*     GEMM(B) · RES(B)
          └─ 쓰기는 동일 (미러)
```

TDP(True Dual Port)로 바꿔도 포트 수는 그대로이고 포트 폭이 72b → 36b 로 절반이 돼
이득이 없습니다.

### PB_Mem 은 "레이어 채널 + 뒤에 한 칸"

엔진은 inst 시작(`S_GCONST`)에 `PB + NOUT` 을 한 번 읽습니다. 그 한 칸이 **레이어마다**
있어야 합니다 — 없으면 다음 레이어의 채널 0 을 읽습니다(실제로 그랬고 결과가 −128 로
포화했습니다).

| 레이어 | 그 칸의 내용 |
|---|---|
| `event_projection`, `preproc`, 각 블록 `linear2` | GELU 뒤 int8 재양자화 곱수 |
| `proc_ev.1`, `clf.linear_1` | 활성함수 뒤 **2차** 재양자화 곱수 |
| `proc_embs.linear1` | 평균(1/96) + 다음 격자 재양자화를 **한 곱수로** |
| 각 블록 `linear1` | 안 씀 — Q4.11 16비트를 그대로 저장(raw16) |

LayerNorm 은 메모리를 **둘** 씁니다 — PG(gamma/beta, 특징별)와 PB(재양자화 스칼라
하나). 베이스가 다르므로 필드도 둘입니다: `PB` = 스칼라 자리, `OSTR` = PG 베이스.

## 8. 설계 근거

### GEMM 3종이 한 코어를 씁니다

시스톨릭 코어는 `C = A·B` 에서 **A·B 둘 다 "워드 = reduce 인덱스, 레인 = non-reduce
인덱스"** 로 읽습니다. EvT 의 GEMM 세 종류를 이 틀에 넣으면 전부 같은 식입니다:

| | 식 | reduce | B 출처 |
|---|---|---|---|
| Linear | `Σ_k A[m][k]·W[n][k]` | k | W_Mem |
| `Q·Kᵀ` | `Σ_d Q[m][d]·K[n][d]` | d = 32 | **A_Mem** |
| `attn·V` | `Σ_j attn[m][j]·V[j][n]` | j = Lk | **A_Mem** |

차이는 **B 를 어느 메모리에서 읽느냐** 하나뿐입니다. `attn·V` 의 A 는 softmax 출력
uint8 [0,127] 인데 이 구간은 int8 해석과 값이 같아 **unsigned 곱셈기가 필요 없습니다.**

### 마스킹 회로가 없습니다

EvT 는 비활성 패치를 마스킹해야 하는데, 호스트가 **활성 토큰만 보내므로** 보드에는
패딩 키가 존재하지 않습니다:

```
Lk = n_tok + 1        (+1 은 bias_k 토큰 — 원래도 절대 마스킹 안 됨)
```

`C = n_tok + 1` 하나가 마스크를 전부 표현합니다. 마스크 비트맵도 −∞ 주입도 필요
없습니다. 근거는 264 샘플 정확도가 정확히 재현된다는 것과, 골든에서 마스크된 키의
softmax 출력이 정확히 0 이라는 것입니다.

### 주소 계획을 파이썬에서 확정합니다

타임스텝당 118 inst 입니다. 주소식을 RTL 안에서 처음 맞추면 디버깅 표면이 감당이 안
됩니다. `sw/schedule_evt.py` 가 영역 할당과 실행 순서를 만들고 **① 영역 겹침
② A_Mem 상한 ③ 생산 전 소비** 를 검사합니다. RTL 은 그 표를 실행만 합니다.

**head-major 가 강제됩니다.** `Q·Kᵀ` 의 reduce 가 `head_dim`(32)이라 B 타일 간격이
32여야 하는데, K 를 채널순으로 저장하면 간격이 128 이라 안 맞습니다:

```
Q[h][mt][d] = Q_base + h*(QT*32) + mt*32 + d
K[h][kt][d] = K_base + h*(KT*32) + kt*32 + d
```

그러면 head h · 행타일 mt 의 QK GEMM 이 `M=32, K=32, Nout=Lk` 로 끝나고 코어는 손댈
게 없습니다.

### inst 프로그램이 정적입니다

`n_tok` 이 타임스텝마다 다른데(16~123), 영역 크기를 거기 맞추면 베이스가 매번 바뀌어
**프로그램을 5,182벌** 만들어야 합니다. 모든 stride 를 최악치로 고정하니 베이스가 전부
상수가 되고, 바뀌는 건 네 필드뿐입니다:

```
VAR[0] M ← n_tok    VAR[1] NOUT ← Lk    VAR[2] K ← Lk    VAR[3] C ← Lk
```

빈 자리는 0 이 채워지고 GEMM 이 그 0 에도 사이클을 씁니다 — 대신 주소 로직이 전부
상수가 됩니다.
