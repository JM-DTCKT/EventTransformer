# EvT 가속기 — DVS128 10-class, ZCU102

DVS 이벤트 카메라의 제스처 인식 모델 **EvT(Event Transformer)** 를 ZCU102(xczu9eg-2)
PL 에 올린 추론 가속기입니다. attention 3블록 · head 4개를 포함한 전체 망이 보드에서
돌고, 264 샘플 정확도가 골든과 일치합니다.

```
양자화    A8W4  활성 int8 / 가중치 int4    가중치 니블 팩, DSP 패킹 미적용
클럭      187.5 MHz  (IOPLL / 8)          WNS +0.022 ns, 실패 엔드포인트 0 / 578,051
정확도    257 / 264 = 97.35 %             A8W8 258/264 = 97.73 % 대비 −1
속도      6,820 µs / 샘플                 264 샘플 1,801 ms · 146.6 샘플/s
전력      10.023 W                        68.4 mJ / 샘플
연산기    DSP48E2 1,974 (78.3 %)          32×32 시스톨릭 배열 1,024 + 주변
메모리    BRAM 379 (41.6 %)               A8W8 443 대비 −64 (−14.4 %)
```

## 1. 보드 실행 결과

ZCU102 실측입니다. 다섯 조건 모두 **같은 264 샘플**을 DDR 에서 읽어 돌렸습니다.
마지막 열만 A8W4 이고 나머지는 A8W8 입니다.

| 264 샘플 총 | 4,426 ms | 2,958 ms | 2,290 ms | 1,801 ms | **1,801 ms** |

| **정확도** | 258 / 264 | 258 / 264 | 258 / 264 | 258 / 264 | **257 / 264 (97.35 %)** |
| 처리율 | 59.6 샘플/s | 89.2 샘플/s | 115.2 샘플/s | 146.6 샘플/s | **146.6 샘플/s** |
| BRAM | 564.0 | 372.5 | 436.5 | 443 | **379** |

**A8W8 네 조건에서는 정확도가 한 샘플도 다르지 않습니다.** 클럭을 1.875배 올리고 RTL 을
아홉 곳 고쳤는데 결과가 동일합니다.

**A8W4 는 시간을 바꾸지 않습니다.** 사이클 수가 A8W8 과 같은데(1,273,508 대 1,273,505,
차이 3사이클은 샘플별 토큰 수 반올림), W4 는 `W_Mem` 의 레인 폭만 줄일 뿐 제어 흐름과
배열 스케줄을 건드리지 않기 때문입니다. 이번 baseline 에서 W4 의 이득은 **BRAM −64 타일
(−14.4 %)과 전력 −0.032 W** 이고 속도 이득은 없습니다. 속도를 얻으려면 DSP48E2 하나에
W4 두 개를 싣는 **DSP 패킹**이 필요하고, 그것이 다음 단계입니다.

정확도는 W8 258 → W4 257 로 한 샘플 줄었습니다 (97.73 % → 97.35 %). 오분류 샘플은
27, 39, 97, 141, 152, 171, 204 입니다.

마지막 열은 클럭을 안 올리고 **사이클만 21 % 줄인** 것입니다 (§8 참고):
RES 를 워드당 1사이클로 파이프라인화(−14.5 %)하고, QK 를 행타일 3개짜리 한 명령어로
합쳐 softmax 가 도는 동안 배열이 멈추지 않게 했습니다(−9.0 %).

한 샘플은 타임스텝 20개 × 24 ms = **480 ms 분량의 이벤트 데이터**입니다. 6.820 ms 에
처리하므로 **실시간 대비 70.4배속**입니다.

**W4 의 실이득은 BRAM 입니다.** `W_Mem` 워드가 32레인 × 8b = 256b 에서 32레인 × 4b =
128b 로 줄어 64타일이 빠졌습니다. LUT 은 레인마다 니블을 int8 로 부호확장하는 조합
논리 때문에 +553 늘었지만, CLB 총량은 오히려 74개 줄었습니다.

**DSP 는 한 개도 안 줄었습니다.** 배열의 B 포트는 여전히 8비트이고, W_Mem 에서 읽은
직후 부호확장해 int8 로 흘리기 때문입니다 (QK·AV 의 B 는 A_Mem 의 int8 이라 경로를
하나로 유지해야 합니다). DSP 를 줄이거나 처리량을 늘리려면 DSP48E2 하나에 W4 두 개를
싣는 패킹이 필요합니다.

```
        │                                        │          └── top        (제어)
        │                                        │
        └── S_AXI_HP0_FPD  (AXI4 128b) ───────── smc_data ──── axi_dma_0  (데이터)
                                                 │                  │
                                                 │            AXI-Stream 128b
                                                 │                  ↓
        DDR ←──────────────────────────────────  │          top ── EvT_Engine

```

**PS 와 PL 은 비동기입니다.** A53 은 APLL(1200 MHz), DDR 은 DPLL(533 MHz), PL 은
IOPLL/8(187.5 MHz)로 서로 다른 PLL 에서 나옵니다. PS-PL AXI 포트에 비동기 FIFO 가
내장돼 있어 **PL 주파수만 바꿔도 PS 는 영향이 없습니다** — 100 → 150 → 187.5 MHz 변경이
`psu_init` 한 줄로 끝난 이유입니다.

## 4. 실행 모델

가속기는 **자기 명령어 프로그램**을 돕니다. CPU 의 fetch–decode–execute 와 같은
구조입니다.

```
IDLE → TLOAD → FETCH → DEC → GCONST → RUN → WAIT → NEXT → … → TSTEP → DONE
                 ↑                                    │
                 └────────── 다음 inst ────────────────┘
```

| 상태 | 하는 일 |
|---|---|
| **TLOAD** | 타임스텝 시작 — 입력 활성값 · `pos_idx` 적재 |
| **FETCH** | `Inst_Mem` 에서 256비트 inst 워드 읽기 |
| **DEC** | `op_kind`·`op_fmt`·`op_ain`·`op_aout` 등으로 펼침 |
| **GCONST** | 상수(bias · 곱수) 준비 3사이클 |
| **RUN** | `op_kind` 에 따라 해당 유닛 기동 |
| **WAIT** | 유닛 완료 대기 (RES · MEAN 은 여기서 직접 위상 기계를 돌림) |
| **NEXT** | inst 포인터 `sp` 증가 |
| **TSTEP** | 타임스텝 경계 — latent 이월 |

### 프로그램 길이

```
body 94 inst   ← 타임스텝마다 반복
tail  5 inst   ← 샘플 끝에 한 번
──────────────
한 샘플 = 94 × T + 5      (T ≤ 20)
```

QK 를 행타일마다 쪼개던 것을 head 당 하나(`M = LAT = 96`)로 합치면서 118 → 94 가
됐습니다 (QK 36 → 12). 명령어 경계가 사라져 **softmax 가 도는 동안 배열이 다음
행타일을 계속 돕니다** — §8 참고.

inst 종류는 7가지입니다: `GEMM` · `LN` · `SMAX` · `RES` · `MEAN` · `ARGMAX` · `POS`.

### 토큰 흐름 제어

타임스텝마다 유효 토큰 수(`n_tok`)가 16~123 으로 달라집니다. 엔진이 `tok_req` 를 올리면
PS 가 해당 타임스텝의 X 타일을 DMA 로 채우고 `tok_ack` 로 답합니다. 샘플당 최대 20회
왕복합니다. PS 오버헤드 전체(폴링 · DMA · 샘플별 latinit/BKV)가 **0.4 %** 로
샘플당 28 µs 입니다 — DMA 는 병목이 아닙니다.

### inst 워드 (256b)

`EvT_Engine.v` 디코더와 한 벌입니다.

```
[ 31: 0] KIND[3:0] FMT[5:4] ACT[7:6] VAR[11:8] FLAG[15:12]
         SHIFT[21:16] SHIFT2[27:22] FLAG2[31:28]
[ 63:32] M        [ 95:64] K        [127:96] NOUT
[159:128] AIN     [191:160] BIN     [223:192] AOUT
[255:224] RQ_BASE[15:0] | OSTR[31:16]

KIND  0 GEMM  1 LN  2 SMAX  3 RES  4 MEAN  5 ARGMAX  6 POS
FMT   0 int8(+ACT)  1 Q4.11→GELU→int8  2 bf16  3 Q6.9(softmax 직결)
VAR   [0] M←n_tok  [1] NOUT←Lk  [2] K←Lk  [3] C←Lk
FLAG  [0] Transpose32 경유  [1] head-major(OSTR=head stride)  [2] B는 A_Mem
      [3] raw16 — Q4.11 을 int8 로 안 내리고 16비트 그대로 저장
FLAG2 [0] LayerNorm 입력이 Q4.11 정수 코드
      [1] RES 두 피연산자가 정수 코드 — RQ_BASE/OSTR 의 정수 scale 로 환산
      [2] B 에 bias 토큰이 붙음 (AOUT=bias_k, OSTR=bias_v, RQ_BASE=스칼라)
      [3] 활성함수 뒤 2차 재양자화
```

필드 하나가 inst 종류에 따라 다른 뜻을 갖습니다 — 워드를 늘리는 대신 **그 inst 에서
확실히 노는 칸**을 씁니다. QK 는 메모리에 안 써서 `AOUT` 이 놀고(bias_k 워드 주소),
`OSTR` 은 softmax 출력 영역(SM)의 베이스로 씁니다. AV 는 행타일이 하나라 `OSTR` 이
놀아 bias_v 주소를 싣습니다 — **AV 를 행타일 병합하지 않은 이유**가 이것입니다.

## 6. 모듈별 설명

### `top` — 보드 최상위

AXI4-Lite 제어 레지스터 파일과 AXI-Stream 데이터 경로를 감싼 래퍼입니다. PS 가 쓰는
레지스터(`start`, `n_body`, `n_tail`, `n_time`, `eps`, `tok_n`, `tok_ack`)를 받아
엔진에 넘기고, 엔진의 `done`·`busy`·`res_class`·`res_logits` 를 되돌려줍니다.
`VERSION` 레지스터(`0xA001_001C` = `0x45565401`)로 비트스트림을 확인합니다.

### `core/` — 엔진 데이터패스

**`EvT_Engine`** (1,029줄, 전체의 20 %)

inst 실행 FSM 이면서, 하위 모듈로 분리되지 않은 로직을 직접 품고 있습니다.

| 내부 블록 | 하는 일 |
|---|---|
| **A_Mem 포트 중재** | 읽기 2포트(`ar_*`/`br_*`)를 GEMM·LN·RES·MEAN·POS 가 나눠 씀. 동시에 도는 유닛이 없도록 스케줄이 보장하되, **GEMM 만은 A 와 B 를 동시에** 읽음 |
| **`RESLANE`** | 잔차 덧셈 32레인. bf16 경로는 `Fp32_Add`, 정수 경로는 곱셈 2개 + `Int32_To_Bf16` |
| **`ARGMAX`** | 최종 분류. `acc·M[c]` 를 64비트로 비교해 최댓값 추적 |
| **`MEAN`** | 평균 풀링. 32입력 덧셈 트리 + 재양자화 |
| **지연선 `nq`/`mq`** | 출력 포맷(2~9단)에 맞춰 A_Mem 쓰기 주소를 늦춰 데이터와 짝을 맞춤 |
| **토큰 핸드셰이크** | `tok_req` / `tok_ack` — PS 가 타임스텝마다 X 를 채워줌 |

**`Format_Cast_Act`**

GEMM 이 뱉는 INT32 누산값을 다음 레이어가 원하는 포맷으로 바꿉니다. bias 덧셈 +
역양자화·재양자화 + 포맷 변환 + 활성함수를 한 파이프라인에 융합해 **추가 사이클 없이**
GEMM 출력에 붙어 흐릅니다.

| `FMT` | 경로 | 단수 |
|---|---|---|
| 0 INT8 | requant → [ReLU] → int8 | 3 |
| 1 Q4.11 | requant → **GELU** → requant → int8 | 9 |
| 2 BF16 | bf16((acc+b) × scale) | 2 |
| 3 Q6.9 | requant → Q6.9 → softmax 직결 | — |

경로마다 길이가 달라, 엔진이 지연선으로 쓰기 주소를 2~9사이클 늦춥니다. GEMM 이 한
사이클에 32개 값을 내놓으므로 후처리도 **32레인 병렬**입니다.

**`Pos_Gather`**

위치 임베딩을 온칩 표에서 찾아 A_Mem 에 씁니다. 예전에는 호스트가 타임스텝마다
pos enc 를 워드 레이아웃으로 펴서 DDR 에 올렸고 그 이미지가 **96.7 MB** 였습니다.
실제 정보량은 표 27.6 KB + `pos_idx` 0.47 MB 뿐이라 200배를 펼쳐 보낸 셈이었습니다.

표를 **행 단위로 넓게**(한 행 = 64특징 = 512b) 두면 한 토큰의 64개 값이 한 번의 읽기로
나오고, 나머지는 축 전환 문제가 됩니다:

```
① 표에서 32행 읽기      96 사이클
② 32×64 버퍼에 쌓기
③ A_Mem 에 64워드 쓰기  64 사이클      ≈ 160 사이클 / 타일
```

타임스텝당 최대 4타일 = 650 사이클로, 전체의 **0.1 %** 입니다.

**`Transpose32`**

32×32 바이트 corner-turn — 행으로 쓰고 열로 읽습니다.

```
쓰기 워드 d :  wdata 의 바이트 t  =  X[t][d]
읽기 워드 t :  rdata 의 바이트 d  =  X[t][d]
```

시스톨릭 코어는 A·B 둘 다 "워드 = reduce 인덱스" 로 읽는데, `attn·V` 만 reduce 축이
`d` → `j` 로 바뀝니다. **V 만 축을 돌려야** 해서 이 모듈이 있습니다.

**`Bram_Sdp`**

**SDP(Simple Dual Port)** — 쓰기 1포트 + 읽기 1포트, 서로 독립된 주소. 바이트 단위
write enable 을 지원하고 읽기 지연은 1사이클입니다. 37줄짜리 이 모듈 하나가 파라미터만
바꿔 **5종류 메모리 전부**를 만듭니다.

### `axi/` — 호스트 인터페이스

**`Axis_Loader`** — AXI-Stream 128b 를 받아 온칩 메모리에 순차 적재합니다. 목적지
(`sel`)와 시작 워드(`base`)를 AXI-Lite 로 잡은 뒤 스트림을 흘리면, 소프트웨어가 넘긴
버퍼가 곧 메모리 이미지가 됩니다. **RTL 에 주소 계산 로직이 없어** 디버깅할 게
없습니다 — 순서 재배치는 전부 호스트 쪽 파이썬이 미리 합니다.

**`Axis_Dump`** — A_Mem 구간을 읽어 DMA S2MM 으로 DDR 에 내보냅니다. **포맷 경계마다
중간 활성값을 대조**해야 해서 결과값만이 아니라 내부 상태를 꺼내올 수 있어야 합니다.
엔진이 쉴 때만 동작합니다 (A_Mem 읽기 포트를 나눠 씀).

### `gemm_core/` — 32×32 시스톨릭 배열

**`Gemm_Core`**

output-stationary 시스톨릭 GEMM. 타일 순서기와 드레인을 담당합니다. `fpga_nl` 판과
**연산은 완전히 동일**하고 딱 하나가 다릅니다 — **B 피연산자의 출처를 코어가 정하지
않고 주소만 내보냅니다.** 그래서 Linear · `Q·Kᵀ` · `attn·V` 세 종류가 코어 한 벌을
씁니다.

공용 타일 순서기(`CLR→STREAM→RD→NEXT`)는 타일이 겹칠 수 없어 쓰지 않고, 여기서만
쓰는 순서기를 직접 둡니다.

**`PE_Array`**

정방 mesh. A 는 좌→우, B 는 위→아래로 흐르고, 여기에 **파면 두 개가 더** 흐릅니다:

```
clr    좌→우    A 와 같은 방향·같은 속도
snap   좌→우    마찬가지
```

둘 다 A 와 같은 속도라 PE[i][j] 는 **자기가 확정되는 사이클에** 값을 받습니다.

**`PE_OS`** — DSP 1,024개의 실체

원본 `PE_OS` 는 누산기가 DSP48E2 의 P 하나뿐이라, 컬럼을 다 뽑아낼 때까지 다음 타일을
시작할 수 없었습니다. 타일 주기 `K+114` 중 실제 곱셈은 `K` 뿐이었습니다.

```
P       : 지금 타일을 누적                 (ping)
shadow  : 직전 타일의 최종값을 들고 있음   (pong)  ← 읽어내기는 여기서
```

**ping-pong 누산기**로 드레인과 다음 타일 계산이 겹칩니다.

**`Skew_Buf`** — 시스톨릭 정렬용 삼각형 지연 버퍼

원래 피더는 레인마다 **다른 주소**를 읽어야 했습니다 (`a_edge[i] = a_mem[mt*N+i][c-i]`).
뱅크 32개가 각각 독립 주소를 받아야 해서 메모리를 32조각으로 쪼개야 했는데, 이 버퍼가
그 요구를 없앱니다 — 메모리는 한 워드씩 읽고, 스큐는 버퍼가 만듭니다.

### `layernorm/`

**`LayerNorm_Top`** — 엔진 어댑터. A_Mem 읽기, affine, 재양자화를 붙여 엔진 규약에
맞춥니다.

**`LayerNorm_Unit`** — 32행 타일 단위 D축 LayerNorm (bf16 in / Q4.11 out).

```
for r in 0..31:  y[r][0..127] = (x[r][.] - mu[r]) / sqrt(var[r] + eps)
```

한 타일은 **32행 × 128열**이고, 매 클럭 "한 열"(32행 × 16b = 512b, A_Mem 워드 폭과 일치)
을 받습니다. 세 단계를 **타일 3개에 걸쳐 파이프라인**합니다:

| 단계 | 하는 일 | 길이 |
|---|---|---|
| S1 | 수신하며 `sum_x`·`sum_x2` 누산 | 128 |
| S2 | 분산 → `rstd` (역제곱근) | 약 38 |
| S3 | 정규화 후 출력 | 128 |

**분산을 정수 그대로** 구해 상쇄오차를 원천 제거합니다:

```
var = 2^-(2IF+2DLOG) · ( (SQ << DLOG) - SX·SX )
```

괄호 안이 오차 없는 정수식이라 Cauchy-Schwarz 에 의해 **결과가 절대 음수가 되지
않습니다.** 나눗셈도 없습니다 — `mu` 는 `SX` 를 소수점만 바꿔 읽은 값입니다.

**`LayerNorm_Affine`** — 곱셈기 1개 + 고정 시프트.

```
y = sat( (xhat·gamma + (beta << BSHIFT) + (1 << (OSHIFT-1))) >> OSHIFT )
```

세 피연산자가 전부 고정소수점 코드라 스케일이 정적으로 정해집니다.

**`Rsqrt_Unit`** — 정규화 + PWL LUT 방식의 역제곱근. `LayerNorm_Unit` 만 씁니다.

### `softmax/`

**`Softmax_Top`** — 엔진 어댑터. 열 수 `n_col`(=Lk)과 **타일 수 `n_tile`(=⌈M/32⌉)**
을 받아 타일을 연달아 처리합니다. `n_col-1` 마다 `in_last` 를 실어 주고 카운터를
**되감습니다** — 이 되감기가 없으면 두 번째 타일의 `in_last` 가 영영 안 뜹니다.
`out_last` 로 타일 경계를 알려 주면 엔진이 SM 쓰기 베이스를 `SMSTR` 만큼 올립니다.

**`Softmax_Unit`** — 32행 타일 단위 T축 softmax (Q6.9 in / Q1.14 out).

`LayerNorm_Unit` 과 같은 구조로 매 클럭 한 열(512b)을 받고, **수신하면서 max 를 확정**
합니다. 별도 패스가 없습니다.

예전 판은 레인 하나를 시분할해 `4·N·C ≈ 6,800` 사이클이 들었고 이를 36번 돌아
**타임스텝 53만 사이클 중 약 24만**을 softmax 가 썼습니다. 새 코어가 그걸 없앴습니다.

RECV/EXP/MUL 3단은 **서로 다른 타일**을 동시에 처리하도록 설계돼 있는데, QK 를
행타일마다 쪼개던 시절에는 명령어당 타일이 하나뿐이라 그 파이프라인이 통째로
놀았습니다 (QK 292 사이클 중 147 이 softmax 대기). `M = 96` 병합으로 세 단이 실제로
겹칩니다.

**`xbuf` 는 4 뱅크입니다.** GEMM 은 행타일 하나를 72 사이클에 배출하는데 S2(exp·합·
역수)는 93 사이클이 걸려 뒤처집니다. `Softmax_Unit` 은 `in_ready` 로 백프레셔를 내지만
**`Gemm_Core` 에는 그 경로가 없어 컬럼이 그대로 유실**됩니다. 한 명령어의 행타일이
최대 3개(QT)라 4벌이면 뱅크를 재사용하지 않아 수신이 멈추지 않습니다. 비용은 BRAM
뿐이라 CLB 압박에 영향이 없습니다.

**`Exp2_Unit`** — softmax 의 exp 입력은 항상 `z = x − max ≤ 0` 이라 `exp(z) ∈ (0,1]`
입니다. 자연지수를 그대로 근사하지 않고 **base-2 로 바꾼 뒤 "정수부는 시프트,
소수부만 LUT"** 로 처리합니다. 레인당 1벌씩 32개.

**`Recip_Unit`** — 나눗셈 `y_i = e_i / S` 를 "역수 한 번 + 곱셈 N 번"으로 바꿉니다.
`S` 는 exp 결과의 합이라 범위가 넓은데, **2의 거듭제곱으로 정규화해 LUT 정의역을
[1,2) 로 좁힙니다.** 행별 1벌.

### `gelu/`

**`Gelu_Pwl`** — Q4.11 → Q4.11 구간선형 GELU. `Gelu_Lut.vh` 에 base/delta 64쌍이
들어 있고, `Format_Cast_Act` 의 Q4.11 경로에서 32레인 병렬로 씁니다.

### `activation/`

**`Activation`** — requantizer 뒤에 붙는 활성함수, 32레인 병렬 순수 조합. 레이어마다
런타임으로 골라야 하므로(마지막 레이어는 활성함수 없음) 파라미터가 아니라 **입력
포트**(`act_sel`)로 선택합니다.

### `requant/`

**`Requant_Int`** — 데이터패스의 유일한 정수 재양자화기 형태입니다.

```
out = sat( (acc·M + (1 << (sh-1))) >> sh )

acc : GEMM 누산기(INT32) 또는 앞단 Qm.n 코드
M   : 오프라인 상수.  M[c] = round(s_x · s_w[c] / lsb_out · 2^sh)
```

**역양자화와 재양자화를 한 곱수로 접어** 곱셈 하나로 끝냅니다. `M[c]` 는 오프라인
캘리브레이션(학습 배치 100개 absmax)에서 정해집니다.

**`Requant_Bf16`** — INT32 → bf16. 100 MHz 대비 타이밍을 위해 **곱셈 뒤에서 한 단**
끊었습니다 (`CP_LAT_B` = 2).

### `vector_alu/`

| 모듈 | 하는 일 |
|---|---|
| **`Fp32_Add`** | FP32 가산기 2단. 잔차 경로에서 씀. 1단은 크기 비교 → 지수 정렬(배럴 시프터) → 가감산, 2단은 정규화. 선행 0 카운트는 **이진 탐색 트리(5단)** — 선형 우선순위 인코더(27단 리플)일 때 `sum1 → y_reg` 가 20 로직단 5.045 ns 로 임계경로였습니다 |
| **`Fp32_To_Bf16`** | FP32 → bf16 (상위 16비트 + 반올림) |
| **`Int32_To_Bf16`** | INT32 → bf16 (LZC + 정규화) |
| **`Bf16_To_Fix`** | bf16 → 고정소수점. `sh = e + SH_OFS + xsh` 라 **입력 지수에 의존** |
| **`Q411_To_Fix`** | Q4.11 → 고정소수점. `sh = SH_OFS + xsh` 로 **입력과 무관** |

`Bf16_To_Fix` 와 `Q411_To_Fix` 는 `LayerNorm_Unit` 의 입력단에서 **병렬로 놓고 mux 로
고릅니다.** 예전에는 Q4.11 을 bf16 으로 올려서 넣었는데, 그러면 정규화(LZC + 좌시프트)와
역정규화(우시프트)가 한 사이클에 **직렬**로 놓여 8.475 ns 가 됐습니다. 각자 목표
포맷까지 바로 가서 mux 로 합치면 깊이가 절반이 됩니다.

## 7. 메모리

| | 폭 × 깊이 | 사용 |
|---|---|---|
| **A_Mem** | 512b × 8,192 **× 2 미러** | 7,649 워드 |
| W_Mem | **128b** × 16,384 (A8W4) | 14,000 워드 (**219 KB**) |
| Requant_Mem | 256b × 1,024 | 860 워드 |
| Affine_Mem | 256b × 256 | 208 워드 |
| Inst_Mem | 256b × 256 | 99 워드 |

W_Mem 의 폭은 `W_W` 파라미터입니다 — **A8W8 이면 256b(437 KB), A8W4 면 128b(219 KB)**.
`rtl/Top.v` 의 `parameter W_W` 하나로 바뀌고, 엔진은 읽은 니블을 즉시 int8 로
부호확장하므로 그 아래 데이터패스는 두 경우가 완전히 같습니다.

### A_Mem 이 미러 2벌인 이유

GEMM 만은 **A 와 B 를 동시에 읽습니다.** `Q·Kᵀ` 와 `attn·V` 는 둘 다 A_Mem 이라
읽기 2포트가 필요한데, RAMB36E2 는 물리적으로 포트가 2개뿐이라 쓰기가 하나를 쓰면
읽기는 하나만 남습니다. **2R+1W 를 동시에 하려면 복사본이 물리적으로 필요합니다.**

```
u_amem0   쓰기 aw_*  ·  읽기 ar_*     GEMM(A) · LN · MEAN · POS · RES(A)
u_amem1   쓰기 aw_*  ·  읽기 br_*     GEMM(B) · RES(B)
          └─ 쓰기는 동일 (미러)
```

TDP(True Dual Port)로 바꿔도 포트 수는 그대로이고 포트 폭이 72b → 36b 로 절반이 돼
이득이 없습니다.

### Requant_Mem 은 "레이어 채널 + 뒤에 한 칸"

엔진은 명령어 시작(`ST_CONST`)에 `RQ_BASE + NOUT` 을 한 번 읽습니다. 그 한 칸이 **레이어마다**
있어야 합니다 — 없으면 다음 레이어의 채널 0 을 읽습니다(실제로 그랬고 결과가 −128 로
포화했습니다).

| 레이어 | 그 칸의 내용 |
|---|---|
| `event_projection`, `preproc`, 각 블록 `linear2` | GELU 뒤 int8 재양자화 곱수 |
| `proc_ev.1`, `clf.linear_1` | 활성함수 뒤 **2차** 재양자화 곱수 |
| `proc_embs.linear1` | 평균(1/96) + 다음 격자 재양자화를 **한 곱수로** |
| 각 블록 `linear1` | 안 씀 — Q4.11 16비트를 그대로 저장(raw16) |

LayerNorm 은 메모리를 **둘** 씁니다 — Affine_Mem(gamma/beta, 특징별)과 Requant_Mem(재양자화
스칼라 하나). 베이스가 다르므로 필드도 둘입니다: `RQ_BASE` = 스칼라 자리,
`OSTR` = Affine_Mem 베이스.

## 8. 설계 근거

### GEMM 3종이 한 코어를 씁니다

시스톨릭 코어는 `C = A·B` 에서 **A·B 둘 다 "워드 = reduce 인덱스, 레인 = non-reduce
인덱스"** 로 읽습니다. EvT 의 GEMM 세 종류를 이 틀에 넣으면 전부 같은 식입니다:

| | 식 | reduce | B 출처 |
|---|---|---|---|
| Linear | `Σ_k A[m][k]·W[n][k]` | k | W_Mem |
| `Q·Kᵀ` | `Σ_d Q[m][d]·K[n][d]` | d = 32 | **A_Mem** |
| `attn·V` | `Σ_j attn[m][j]·V[j][n]` | j = Lk | **A_Mem** |

차이는 **B 를 어느 메모리에서 읽느냐** 하나뿐입니다. `attn·V` 의 A 는 softmax 출력
uint8 [0,127] 인데 이 구간은 int8 해석과 값이 같아 **unsigned 곱셈기가 필요 없습니다.**

### 마스킹 회로가 없습니다

EvT 는 비활성 패치를 마스킹해야 하는데, 호스트가 **활성 토큰만 보내므로** 보드에는
패딩 키가 존재하지 않습니다:

```
Lk = n_tok + 1        (+1 은 bias_k 토큰 — 원래도 절대 마스킹 안 됨)
```

`C = n_tok + 1` 하나가 마스크를 전부 표현합니다. 마스크 비트맵도 −∞ 주입도 필요
없습니다. 근거는 264 샘플 정확도가 정확히 재현된다는 것과, 골든에서 마스크된 키의
softmax 출력이 정확히 0 이라는 것입니다.

### 주소 계획을 파이썬에서 확정합니다

타임스텝당 94 inst 입니다. 주소식을 RTL 안에서 처음 맞추면 디버깅 표면이 감당이 안
됩니다. `sw/schedule_evt.py` 가 영역 할당과 실행 순서를 만들고 **① 영역 겹침
② A_Mem 상한 ③ 생산 전 소비** 를 검사합니다. RTL 은 그 표를 실행만 합니다.

**head-major 가 강제됩니다.** `Q·Kᵀ` 의 reduce 가 `head_dim`(32)이라 B 타일 간격이
32여야 하는데, K 를 채널순으로 저장하면 간격이 128 이라 안 맞습니다:

```
Q[h][mt][d] = Q_base + h*(QT*32) + mt*32 + d
K[h][kt][d] = K_base + h*(KT*32) + kt*32 + d
```

그러면 head h · 행타일 mt 의 QK GEMM 이 `M=32, K=32, Nout=Lk` 로 끝나고 코어는 손댈
게 없습니다.

### inst 프로그램이 정적입니다

`n_tok` 이 타임스텝마다 다른데(16~123), 영역 크기를 거기 맞추면 베이스가 매번 바뀌어
**프로그램을 5,182벌** 만들어야 합니다. 모든 stride 를 최악치로 고정하니 베이스가 전부
상수가 되고, 바뀌는 건 네 필드뿐입니다:

```
VAR[0] M ← n_tok    VAR[1] NOUT ← Lk    VAR[2] K ← Lk    VAR[3] C ← Lk
```

빈 자리는 0 이 채워지고 GEMM 이 그 0 에도 사이클을 씁니다 — 대신 주소 로직이 전부
상수가 됩니다.

### 사이클을 줄인 두 가지 — 연산기를 안 늘리고 21 %

`tb_evt_tim` 으로 명령어별 위상을 재 보니 배열이 **전체의 46 % 를 놀고** 있었습니다.
GEMM 발행 자체는 이미 90.3 % 효율(유효 MAC / 배열 MAC)이라 짜낼 게 없었고, 노는 쪽에
답이 있었습니다.

**① RES 파이프라인화 (−14.5 %)**

잔차 덧셈이 명령어 8개로 사이클의 **18 %** 를 먹었습니다. `rs_ph` 가 0→4 를 다 돈 뒤에야
다음 워드로 넘어가 **모든 유닛이 5분의 4를 놀았습니다**. 5단은 지연이지 처리율 한계가
아니라, 매 사이클 새 워드를 발행하도록 고쳤습니다. 행타일 베이스는 곱셈 없이
누적(`rs_base_*`)해 주소 경로를 지켰습니다.

```
14,777 → 3,041 사이클   ·  쓰기 가동률 20 % → 97.7 %  ·  이론 최소 384 대비 396
```

**② QK 행타일 병합 (−9.0 %)**

QK 를 행타일마다 쪼개던 것이 두 가지를 동시에 망가뜨리고 있었습니다 — 명령어마다
드레인 64 사이클이 노출되고, `Softmax_Unit` 의 3단 파이프라인이 타일 하나뿐이라
텅 비었습니다.

```
QK 명령어 하나 (이전 3개 = 876 사이클)
  GEMM 발행    216 → 216    연산량 동일
  드레인       192 →  64    −128
  디코드        15 →   5    −10
  softmax 대기 441 → 191    −250   ← 3단이 실제로 겹침
                    ─────
                     480
```

배열이 하는 일의 양은 **1도 안 변했습니다.** 명령어 경계를 없앤 것뿐입니다.

**같이 필요했던 것** : `Softmax_Top` 의 카운터 되감기, `xbuf` 4 뱅크(백프레셔 경로
부재 보완), 엔진의 SM 쓰기 베이스 누적. 그리고 병합만으로는 WNS 가 −0.127 이라
타이밍을 네 곳 고쳤습니다 — `Fp32_Add` 트리 LZC, LayerNorm S3 상수 복제, 복제 4→8벌,
`SRAM_LAT` 1→2 (BRAM 내장 출력 레지스터).

```
WNS −0.006(기준) → −0.127 → −0.102 → +0.016     실패 엔드포인트 0
CLB 95.85 % → 95.43 %                            BRAM +7 타일
```

### 10.2 시뮬레이션 — pull 직후 바로

```bash
cd tb
./run_vcs.sh tb_evt        # 1 타임스텝, 17개 탭을 골든과 대조
./run_vcs.sh tb_evt_t      # 20 타임스텝 종단, 최종 클래스만 판정

```

기대 출력:

```
tb_evt        23/140170 failed      res_class = 9   (골든 pred 9, label 9)
tb_evt_t      TEST PASSED           res_class = 9   1,219,645 사이클
tb_accel_evt  13 checks, TEST PASSED
```

**`tb_accel_evt` 가 보드 경로를 대신 검증합니다.** `tb_evt`·`tb_evt_t` 는 `ld_data` 를
직접 구동해 `Axis_Loader` 를 우회하지만, `tb_accel_evt` 는 AXI-Lite 로 로더를 arm 하고
AXI-Stream 으로 워드당 2 beat 를 흘립니다 — A8W4 에서 상위 beat 가 0 인 것까지 보드와
같습니다 (§10.5 ③).

`tb_evt_head` 는 **RES 파이프라이닝 이후 stale 입니다.** 앞단 세 탭(`PIN`·`PRE`·`EV1`)은
완전 일치하지만 `EV4`(RES 전 스냅샷)와 `EV`(+x bf16)는 2,033개가 어긋납니다. RES 가
워드당 1사이클로 바뀌면서 스냅샷 탭의 의미가 달라진 탓이고 A8W4 와는 무관합니다 —
`tb_evt.v` 는 같은 이유로 이 두 검사를 아예 갖고 있지 않습니다. 검사를 지워 초록으로
만들지 않고 남겨 두었습니다.

`tb_evt` 의 23개는 **실패가 아니라 허용 밴드 초과**입니다. 전부 5~6 LSB 이고 해당 탭의
허용치가 4 입니다. 하드웨어 LayerNorm 이 역제곱근 **근사**를 쓰는 반면 골든은 정확
연산이라 ±1~2 가 나고, W4 는 가중치 스텝이 16배 굵어 그 꼬리가 밴드를 살짝 넘습니다.
허용치는 A8W8 기준으로 튜닝된 값이라 그대로 두었습니다.

앞단 세 탭은 **허용치 0 으로 완전 일치**합니다 (`PIN` 8320/8320, `PRE` 6656/6656,
`EV1` 6656/6656) — 니블 언팩·부호확장·MAC·requant·GELU 가 비트 정확하다는 뜻입니다.

### 10.4 A8W8 ↔ A8W4 전환

가중치 폭은 **RTL 파라미터 하나**지만, TB 와 데이터도 같이 맞춰야 합니다.

| | A8W8 | A8W4 |
|---|---|---|
| `rtl/Top.v` `parameter W_W` | `8` | **`4`** |
| `tb/tb_evt*.v` `localparam W_W` | `8` | **`4`** |
| `pack_evt.py` | `--w_pack_bits 8` | **`--w_pack_bits 4`** |
| `fpga_export` 하위 | `DVS128_10` | **`DVS128_10__a8w4`** |
| `data/wmem.bin` | 448,000 B | **224,000 B** |

`data/` 한 벌을 다시 만드는 전체 명령은 아래와 같습니다.

**앞의 두 단계는 이 커밋의 `data/` 를 바이트 단위로 재현하는 것을 확인했습니다** —
`pack_evt.py` 가 `wmem` · `rqmem` · `afmem` · `latinit` · `bkv` · `posmem` · `config.json`
을, `schedule_evt.py` 가 `instmem.bin` · `schedule.json` 을 그대로 냅니다.
`golden_insts.py` 는 학습 체크포인트를 읽으므로 같은 체크포인트가 있어야 합니다
(§10.5 ②).

```bash
cd sw
python pack_evt.py     --export DVS128_10__a8w4 --dst ../data --w_pack_bits 4
python schedule_evt.py --dst ../data
python golden_insts.py --sample 0 --tstep 0 --dst ../data/golden
python export_board_evt.py --data ../data
```

### 10.5 실제로 겪은 함정 넷

**① `schedule_evt.py` 가 다른 `config.json` 을 보는 경우.**
`--dst` 를 줘도 SHIFT 주석 단계가 고정 경로의 `config.json` 을 읽어, A8W8 SHIFT
(33/31/39)가 A8W4 명령어에 박혔습니다. 정답과 정확히 **+4 = 2⁴** 차이인데, 이는
W4 의 `s_w` 가 16배 커진 것과 같은 크기입니다. 지금은 두 호출부 모두 `--dst` 의
config 를 보도록 고쳤습니다. 증상은 `tb_evt` 91,609 실패였습니다.

**② 골든과 가중치의 출처가 어긋나는 경우.**
`golden_insts.py` 는 체크포인트에서 모델을 세우고 `fpga_export` 의 payload 를 얹습니다.
**둘이 다른 학습 결과면** 앞단 GEMM 은 맞는데 residual stream(bf16)만 어긋나, 중간
탭이 수십 배 차이 납니다. 실제로 `TLATV` 가 하드웨어 ±7.9 대 골든 ±294(40배)로
벌어졌고, 골든을 같은 export 로 다시 만들자 ±7.5 로 정상화되며 실패가 17,751 → 23 이
됐습니다. **골든은 반드시 `wmem.bin` 을 만든 것과 같은 export 로 생성하세요.**

**③ `Axis_Loader` 의 `SEL_W` 는 워드당 2 beat 고정.**
A8W4 의 `W_Mem` 워드는 128b(1 beat)뿐이라, 니블팩 `wmem.bin`(224 KB)을 그대로 DMA 하면
엔진이 쓰는 `ld_data[127:0]`(첫 beat)만 남고 **16 B 마다 하나씩 버려집니다.** 그래서
`export_board_evt.py` 가 32 B 로 패딩한 `data/board/wmem_ddr.bin`(448 KB)을 만들고,
`board/load_ddr.tcl` 이 그것을 올립니다. A8W8 이면 패딩 없이 `wmem.bin` 과 바이트
동일합니다. **시뮬레이션 TB 는 `ld_data` 를 직접 구동해 로더를 우회하므로 이 경로를
검사하지 않습니다** — 보드에서만 드러납니다.

**④ VCS 증분 판정.**
`run_vcs.sh` 는 매번 `simv_*` 와 `.daidir` 를 지우고 다시 컴파일합니다. 바이너리만
지우면 VCS 가 "design hasn't changed" 로 컴파일을 건너뛰어 **직전 바이너리가 그대로
돌거나**, 아예 안 만들어져 조용히 실패합니다. 스크립트를 고칠 때 이 두 줄을 지우지
마세요.
